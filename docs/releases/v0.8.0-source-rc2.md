# RP2040 Fan Control 0.8.0-source-rc2

Draft release notes for a GitHub **pre-release**, not a stable release.

## Changes

- Source-built, self-contained Unraid PLG with pinned pyserial 3.5 and source/payload correspondence verification.
- Persistent JSON HDD/CPU assignments and explicit serial-port selection.
- WebUI service/mode controls, live telemetry and request-specific command confirmation.
- Fixed mode POST completion inside Unraid's renderer so it does not exit midway through the surrounding page.
- Protected single-instance locking, short-write detection, source warnings and immediate thermal fallback.
- Opt-in boot restoration and startup respecting ENABLE, including `/var/run -> /run` handling.
- Transactional baseline backup and verified recovery/removal preserving persistent settings and logs.
- A preview update definition adds pluginURL and normalizes the internal name for Unraid selectors without changing the reviewed runtime or transaction scripts.

## Validation and limits

CI covers Python 3.11/3.12, PHP syntax and form/IPC contracts, protected locking, payload/source and pinned-wheel correspondence, deterministic builds, metadata-only update definition generation, and isolated lifecycle/boot simulations. Review the CI on the exact commit selected for publication.

The firmware does not return a serial ACK; transmitted percentages are command values and not measured RPM. Source ownership, license and security review remain part of release approval. Operational logs and per-installation identifiers are not release assets.

## Installation/update behavior

Back up configuration and the installed definition. Use the existing helper to stop the service before installing an update. Installation preserves configuration/logs and leaves the daemon disabled. Configure sources before explicitly enabling and starting it. Reboot startup respects ENABLE. Uninstall restores the verified baseline and disables startup; it preserves persistent configuration, logs and backups.

The preview update URL stays on `source-tree-review`. It reports the latest deliberately reviewed preview definition. A future stable release must configure its own stable update URL and verify its availability before distributing that definition. Do not use a draft or nonexistent GitHub asset URL as pluginURL.

## Publication procedure

1. Review the source-tree-review pull request, the source-built RC2 artifact and preview opening-tag metadata delta.
2. Verify the latest CI and download the preview installation pair above. Check its checksum before attaching it.
3. Reuse the existing release draft only after reviewing its earlier attachments. The reviewed asset pair for this version must be clearly identified; older preparation ZIPs are not this installer.
4. Set the tag to `v0.8.0-source-rc2`, select the reviewed commit, use the title above and these release-note sections, and enable the pre-release flag.
5. Review the draft, its target commit and attachments before publishing. After publication verify that both installer and checksum download correctly.
6. Keep the preview branch available. Do not merge or promote to stable until the repository's publication checklist has been completed.

The repository tools and connected GitHub operations prepare the code, notes and pull request. Release creation/editing and asset upload require GitHub release-capable access or the repository owner's release editor. No stable publication or merge is implied by this document.
